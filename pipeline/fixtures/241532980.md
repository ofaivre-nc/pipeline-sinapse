# But & scénarios

- **Consultation de la liste** : L'utilisateur ouvre la vue "Mes favoris" et récupère la liste ordonnée de ses objets métiers favoris.
- **Ajout d'un favori** : L'utilisateur ajoute l'objet métier courant à ses favoris depuis son cartouche identité.
- **Retrait d'un favori** : L'utilisateur retire un objet métier de ses favoris.
- **Réorganisation** : L'utilisateur réordonne sa liste de favoris via les boutons Monter/Descendre ou par glisser-déposer.

### DTO imbriqué : FavoriMetadonnees (polymorphe par typeRessource)

Objet d'enrichissement contextuel calculé par le BFF. Sa structure varie selon `typeRessource`. Il est **toujours read-only** et n'est jamais transmis en entrée.

## GET /favoris

- **Objet** : Récupérer la liste ordonnée de tous les favoris de l'utilisateur connecté, tous types confondus, enrichis par le BFF.
- **Paramètres** :

  - `typeRessource` (query, optionnel, enum `PERSONNE` | `DOCUMENT` | `FILTRE`) : filtre la liste par type. Si absent, tous les types sont retournés.
- ** Appel** : 

  - déclenché à l'ouverture de la vue "Mes favoris" (menu **En-tête > Mes favoris**). 
  - déclenché à l'ouverture d’une page de recherche. Le paramètre `typeRessource`= FILTRE. 
- **Comportement BFF** : pour chaque favori, le BFF résout en parallèle le libellé et les métadonnées de la ressource référencée.
- **Réponses** :

  - `200 OK` + `FavoriListItem[]` (tableau ordonné, pouvant être vide `[]`)
  - `400 Bad Request` - valeur de `typeRessource` invalide ([Règles génériques utilisables pour les API](../../Regles-generiques-utilisables-pour-les-API.md))
  - `401 Unauthorized` - session invalide ([Règles génériques utilisables pour les API](../../Regles-generiques-utilisables-pour-les-API.md))
  - `403 Forbidden` - habilitation insuffisante ([Règles génériques utilisables pour les API](../../Regles-generiques-utilisables-pour-les-API.md))

## GET /favoris/types-ressource

- **Objet** : Retourner la liste des types de ressources favorisables disponibles dans l'application. Endpoint inversé permettant à l'IHM d'alimenter dynamiquement les filtres ou les libellés.
- **Paramètres** : aucun.
- **Appel** : déclenché à l'initialisation de la vue "Mes favoris" si l'IHM propose un filtrage par type.
- **Réponses** :

  - `200 OK` + `TypeRessourceFavori[]`
  - `401 Unauthorized` ([Règles génériques utilisables pour les API](../../Regles-generiques-utilisables-pour-les-API.md))

## POST /favoris

- **Objet** : Ajouter une ressource (personne, document ou filtre) aux favoris de l'utilisateur connecté.
- **Request DTO** : `FavoriCreate`
- **Appel** :

  - Type `PERSONNE` : bouton étoile `_IHM_FAV_BoutonAjout_` dans le cartouche identité de la personne.
  - <mark style="background:#dfd8fd">Type </mark>`DOCUMENT`<mark style="background:#dfd8fd"> : bouton étoile dans la vue de consultation documentaire (cf. CU à créer).</mark>
  - Type `FILTRE` : bouton "Sauvegarder la recherche".
- **Étapes** :

1. Validation du corps : `typeRessource` dans l'énumération autorisée, `idRessource` non nul → `400 RG-API-1`.
2. Vérification que la ressource existe et est accessible selon son type :

  - `PERSONNE`: appel interne `GET /personnes/{idRessource}` → `404 FAV-NOT-001` si introuvable, `403 AUTH-HAB-001` si droits insuffisants.
  - `DOCUMENT`<mark style="background:#dfd8fd"> : appel interne </mark>`GET /documents/{idRessource}`<mark style="background:#dfd8fd"> → </mark>`404 FAV-NOT-003`<mark style="background:#dfd8fd"> si introuvable,  </mark>`403 AUTH-HAB-001`<mark style="background:#dfd8fd"> si droits insuffisants.</mark>
  - `FILTRE` : vérification que les critères fournis dans `metadonnees.criteres` sont valides selon le `moduleRecherche` → `400 FAV-VAL-002` si invalides.
3. Vérification que la ressource n'est pas déjà en favori → `409 FAV-BUS-001`.
4. Vérification du quota (tous types confondus) < {quotafavoris} (avec quotafavoris un paramètre administrable) → `422 FAV-BUS-002`.
5. Insertion avec `ordre = 1`, décalage des ordres existants.
6. Retour du favori enrichi.

- **Réponses** :

  - `201 Created` + `FavoriListItem` + Header `Location: /favoris/{idFavori}`
  - `400 Bad Request` - corps invalide ou critères de filtre invalides
  - `401 Unauthorized` ([Règles génériques utilisables pour les API](../../Regles-generiques-utilisables-pour-les-API.md))
  - `403 Forbidden` - droits insuffisants sur la ressource cible
  - `404 Not Found` + `FAV-NOT-001` (personne introuvable) ou `FAV-NOT-003` (document introuvable)
  - `409 Conflict` + `FAV-BUS-001` - ressource déjà en favori
  - `422 Unprocessable Entity` + `FAV-BUS-002` - quota de {quotafavoris} favoris atteint

## DELETE /favoris/{idFavori}

- **Objet** : Retirer un favori de la liste, quel que soit son type, son statut ou son accessibilité.
- **Type** : Hard delete sur l'entrée favori. La ressource référencée n'est pas affectée.
- **Paramètres** :

  - `idFavori` (path param, UUID) : identifiant technique du favori à supprimer.
- **Appel** : bouton `_IHM_FAV_BoutonRetrait_` depuis la vue "Mes favoris", ou icône étoile active depuis la ressource concernée - cf. CU-PORTAIL-FAVORIS.GERER, étapes 4.c, CA-1 3.b, CA-2 3.b.
- **Comportement** : accessible même si la ressource est inaccessible ou supprimée. Comportement idempotent si le favori est introuvable.
- **Réponses** :

  - `204 No Content` - suppression réussie
  - `400 Bad Request` - `idFavori` n'est pas un UUID valide ([Règles génériques utilisables pour les API](../../Regles-generiques-utilisables-pour-les-API.md) )
  - `401 Unauthorized` ([Règles génériques utilisables pour les API](../../Regles-generiques-utilisables-pour-les-API.md) )
  - `403 Forbidden` ([Règles génériques utilisables pour les API](../../Regles-generiques-utilisables-pour-les-API.md) )
  - `404 Not Found` + `FAV-NOT-002` - favori introuvable *(ignoré silencieusement par l'IHM)*

## PATCH /favoris/ordre

- **Objet** : Mettre à jour l'ordre d'affichage des favoris.
- **Request DTO** : `FavoriOrdreUpdate`
- **Appel** : boutons `_IHM_FAV_BoutonMonter_` / `_IHM_FAV_BoutonDescendre_`, ou drop lors d'un glisser-déposer - cf. CU-PORTAIL-FAV.GERER.
- **Mécanisme** :

  - Le corps contient la liste complète et ordonnée des `idFavori` (UUID) de l'utilisateur.
  - Le backend vérifie que chaque `idFavori` appartient bien aux favoris de l'utilisateur → `400 FAV-VAL-001`.
  - La valeur `ordre` de chaque favori est recalculée selon la position dans la liste (position + 1).
- **Réponses** :

  - `200 OK` + `FavoriListItem[]` - liste complète réordonnée
  - `400 Bad Request` + `FAV-VAL-001` - un ou plusieurs `idFavori` invalides ou non présents dans les favoris
  - `401 Unauthorized` ([Règles génériques utilisables pour les API](../../Regles-generiques-utilisables-pour-les-API.md) )
  - `403 Forbidden` ([Règles génériques utilisables pour les API](../../Regles-generiques-utilisables-pour-les-API.md) )
